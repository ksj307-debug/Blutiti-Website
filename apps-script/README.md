# 예약 시트 → Supabase 자동 동기화 (Google Apps Script)

구글 시트 **"블루티티 예약관리_자동화"**의 `Sheet1` 예약 데이터를 Supabase `bookings` 테이블로 15분마다 보내요.

- 코드: [`sync-bookings.gs`](sync-bookings.gs)
- 먼저 Supabase SQL Editor에서 `supabase/migrations/001_init.sql`을 실행해 `bookings` 테이블을 만들어 두세요.

## 준비물

| 이름 | 어디서 찾나요 |
|---|---|
| `SUPABASE_URL` | Supabase 대시보드 → Project Settings → Data API → **Project URL** (예: `https://abcd1234.supabase.co`) |
| `SUPABASE_SECRET_KEY` | Supabase 대시보드 → Project Settings → API Keys → **Secret keys** 의 `sb_secret_...` 키 |

> secret 키는 DB를 마음대로 읽고 쓸 수 있는 열쇠예요. 시트 셀, 메신저, 코드에 붙여넣지 말고 아래 3단계의 **스크립트 속성**에만 넣어 주세요.

## 설치 순서

1. **Apps Script 열기**
   구글 시트 "블루티티 예약관리_자동화"를 열고, 위 메뉴 **확장 프로그램 → Apps Script**를 눌러요. 새 탭에 코드 편집기가 열려요.

2. **코드 붙여넣기**
   왼쪽 `Code.gs`(또는 `코드.gs`) 안의 내용을 모두 지우고, `sync-bookings.gs` 파일 내용을 전부 복사해 붙여넣어요. 위쪽 **저장(디스크 모양)** 아이콘을 눌러요.

3. **스크립트 속성에 값 2개 입력**
   왼쪽 맨 아래 **톱니바퀴(프로젝트 설정)** → 아래로 내려 **스크립트 속성** → **스크립트 속성 추가**를 눌러 두 줄을 넣고 **스크립트 속성 저장**을 눌러요.
   - 속성: `SUPABASE_URL` / 값: Project URL (끝에 `/` 없이)
   - 속성: `SUPABASE_SECRET_KEY` / 값: `sb_secret_...` 키

4. **setup 1회 실행**
   왼쪽 **<> (편집기)**로 돌아와서, 위쪽 함수 선택 칸에서 `setup`을 고르고 **실행**을 눌러요.

5. **권한 승인**
   처음 실행하면 "승인 필요" 창이 떠요. **권한 검토 → 내 구글 계정 선택**을 해요.
   "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음)**을 누르고 **허용**을 눌러요. 직접 만든 스크립트라서 나오는 안내예요.
   실행 로그에 아래 줄이 보이면 성공이에요.
   - `15분 자동 동기화 트리거를 만들었어요`
   - `사진링크 헤더를 추가했어요`, `진행상태 헤더를 추가했어요` (이미 있으면 안 나와요)
   - `진행상태 열에 드롭다운을 설정했어요`

6. **'지금 동기화'로 테스트**
   구글 시트 탭으로 돌아가 **새로고침(F5)** 하면 위 메뉴에 **블루티티**가 생겨요. **블루티티 → 지금 동기화**를 누르면 오른쪽 아래에 `전송 N건, 실패 N건` 알림이 떠요.
   (처음 누를 때 권한 창이 한 번 더 뜰 수 있어요. 5단계처럼 허용해 주세요.)

7. **Supabase Table Editor에서 확인**
   Supabase 대시보드 → **Table Editor → bookings**를 열어 시트의 예약이 들어왔는지 봐요.
   - `phone_last4`(전화번호 뒷 4자리), `expires_at`(이용일시 + 3개월)은 자동으로 채워져요.
   - 이후로는 15분마다 자동으로 동기화돼요.

## 동작 요약

- 1행 헤더 이름으로 열을 찾아요. 열 순서가 바뀌어도 괜찮아요.
- 예약번호가 있는 행만 보내고, 같은 예약번호는 덮어써요(upsert). 100건씩 나눠 보내요.
- **사진링크·진행상태가 비어 있으면 그 칸은 보내지 않아요.** DB에 이미 있는 값이 지워지지 않아요.
- 진행상태가 7단계(촬영 완료, 원본 전달, 셀렉 완료, 보정 중, 보정본 확인, 인화·발송, 완료)가 아니면 그 칸만 빼고 보내요.
- 이용일시·신청일시는 한국시간(+09:00)으로 바꿔 보내요.
- 예약번호는 글자로, 결제금액은 쉼표를 뺀 정수로, 앞자리 0이 빠진 전화번호는 0을 붙여 보내요.
- 로그에는 `전송 N건, 실패 N건`과 문제가 있는 **예약번호**만 남겨요. 이름·전화번호·이메일은 남기지 않아요.
- 실행 기록은 Apps Script 왼쪽 **실행(≡ 모양)** 메뉴에서 볼 수 있어요.

## 문제 해결

| 로그 | 이렇게 해 주세요 |
|---|---|
| `스크립트 속성 ... 를 먼저 입력해 주세요` | 3단계를 다시 확인해요. 속성 이름은 대문자·밑줄까지 똑같아야 해요. |
| `HTTP 401` | 키를 다시 복사해 넣어요. 그래도 401이면 Supabase가 Apps Script 요청을 브라우저로 판단해 secret 키를 막은 경우일 수 있어요. 이때는 Project Settings → API Keys → **Legacy API Keys**의 `service_role` 키(`eyJ...`)를 `SUPABASE_SECRET_KEY`에 넣어 보세요. 코드가 두 종류 키를 모두 알아서 처리해요. |
| `오류코드 42501` | `service_role`에 권한이 없어요. `001_init.sql`을 SQL Editor에서 다시 실행해요. |
| `HTTP 404` 또는 `오류코드 42P01` | `SUPABASE_URL`이 맞는지, `001_init.sql`을 실행했는지 확인해요. |
| `시트 1행에서 헤더를 찾지 못했어요: ...` | 1행 헤더 글자가 정확히 같은지 확인해요 (예: `이메일(예약자정보)`, `주차(차량번호)`). |
| `예약자 또는 전화번호가 비어 있어 보내지 않음` | 그 예약번호 행의 예약자·전화번호를 채워요. DB에서 두 칸은 꼭 있어야 해요. |

자동 동기화를 멈추려면 Apps Script 왼쪽 **트리거(시계 모양)**에서 `syncBookings` 트리거를 삭제하면 돼요.
